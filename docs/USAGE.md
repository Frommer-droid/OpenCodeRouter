# Руководство OpenCode Router

[← README](../README.md) · [English overview](../README.en.md)

Команды выполняются из корня проекта. Сначала настройте интеграцию, описанную в README.

## Графическое приложение

GUI показывает текущий узел, внешний IPv4, состояние API, задержку и сохранённые результаты всех узлов. Таблица сортируется нажатием на любой заголовок; в столбце «Узел» порядок определяется по первым русским буквам названия страны, а повторное нажатие меняет направление. Пустые результаты остаются внизу. Из окна можно переключить маршрут, временно проверить узел, найти лучший вариант или получить другой IP. Кнопка «Другой IP» идёт по алфавиту от текущего узла, пропускает нерабочие варианты и останавливается на первом рабочем узле с новым IPv4; после конца списка поиск продолжается с начала. Если IP текущего неработающего узла определить нельзя, выбирается первый следующий рабочий узел. После успешной окончательной смены программа закрывает в Clash только старые соединения `opencode.exe`, относящиеся к группе `OpenCode-Location`: OpenCode переподключается через новую локацию без перезапуска, а соединения других программ не затрагиваются. Долгие проверки выполняются через `QProcess`, поэтому интерфейс остаётся отзывчивым.

Пока программа запущена, она каждые 5 минут проверяет только текущий маршрут. Исправная проверка проходит без уведомления. Если маршрут перестал отвечать, программа автоматически запускает тот же последовательный перебор «Другой IP» и останавливается на первой рабочей локации. Windows показывает уведомления при запуске программы, начале и успешном завершении переключения, отсутствии рабочих локаций и потере связи с Clash. Нажатие на уведомление открывает окно приложения.

Крестик окна не завершает приложение: окно скрывается, а маршрутизатор остаётся в системном лотке Windows. Кликните значок или выберите «Показать» в его контекстном меню, чтобы вернуть окно. Полностью завершить приложение можно пунктом «Выход» там же. Пока выполняется проверка или временное переключение, выход блокируется до безопасного восстановления маршрута.

Первоначальная установка:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

После этого дважды щёлкните `OpenCode Router-run.cmd`. Для запуска без консольного окна напрямую:

```powershell
Start-Process .\.venv\Scripts\pythonw.exe -ArgumentList .\OpenCodeRouter.pyw
```

В правом верхнем углу находится поправка масштаба 50–150%. Она применяется поверх автоматического масштаба экрана и сохраняется вместе с положением и размером окна в локальном `settings.json`.

## Командная строка

Для прежнего текстового меню можно дважды щёлкнуть `OpenCode Router CLI-run.cmd`. Или откройте PowerShell 7 в папке проекта:

```powershell
pwsh -NoProfile -File .\OpenCodeRouter.ps1 menu
pwsh -NoProfile -File .\OpenCodeRouter.ps1 status
pwsh -NoProfile -File .\OpenCodeRouter.ps1 list
```

Для обеих оболочек нужны работающий Clash Verge Rev, включённый TUN и PowerShell 7. GUI дополнительно требует Python 3.12 и PySide6 в проектной `.venv`; CLI не требует установки Python-зависимостей.

## Команды

| Команда | Действие |
| --- | --- |
| `status`, `check` | Свежий IPv4 и сетевой health-check выбранного узла через диагностический listener |
| `list` | Реальные имена узлов и результаты последних проверок с датой; ничего не переключает |
| `scan` | Временно перебрать и проверить все разрешённые узлы, затем вернуть исходный маршрут |
| `use "имя"` | Выбрать узел, проверить; при неудаче восстановить предыдущий |
| `test "имя"` | Временно выбрать и проверить; затем всегда вернуть прежний узел |
| `auto` | Проверить узлы и выбрать рабочий; учитывать cooldown и минимальное улучшение |
| `auto -DifferentIp` | Просканировать с требованием другого фактического IPv4; явная команда обходит cooldown |
| `menu` | Интерактивный выбор |

```powershell
pwsh -NoProfile -File .\OpenCodeRouter.ps1 use "ИМЯ-УЗЛА-ИЗ-LIST"
pwsh -NoProfile -File .\OpenCodeRouter.ps1 test "ИМЯ-УЗЛА-ИЗ-LIST"
pwsh -NoProfile -File .\OpenCodeRouter.ps1 scan
pwsh -NoProfile -File .\OpenCodeRouter.ps1 auto
pwsh -NoProfile -File .\OpenCodeRouter.ps1 status -Json
```

Копируйте имена из `list`: emoji и пробелы являются частью имени. `-Json` выдаёт структурированный результат; auto дополнительно показывает ход сканирования. Exit code: 0 — успешная команда, 2 — отрицательная проверка, 1 — ошибка или неуспешное переключение.

## Что проверяется

Listener `127.0.0.1:7900` направляет проверки прямо в `OpenCode-Location`. IPv4-проверки и API выполняются одновременно с общим сроком 8 секунд на узел. После успешного IP и завершения API оставшаяся IP-проверка отменяется. Задержка — время этих проверок, не ICMP ping. Длительность полного сканирования зависит от числа узлов и заданного timeout.

Google profile проверяет `/v1beta/models`. HTTP 200/400/401 и JSON 403 с API error подтверждают сетевую доступность; HTML 403, известные сообщения о региональной блокировке, 404, 429, 5xx и timeout не проходят. Ответ «нужен API-ключ» **не доказывает**, что авторизованный запрос к модели будет успешен. Ключи провайдеров инструменту не передаются.

Сравнивается IPv4 с IPv4. Адреса динамические; другой display-name сам по себе не означает другой IP. `-DifferentIp` сравнивает измеренный исходный адрес с кандидатом и повторно проверяет результат после выбора.

## Настройки

`OpenCodeRouter.config.json` — локальный, исключён из Git. `controllerPipe: "verge-mihomo"` использует существующий Windows named pipe с Clash REST API. При непустом `controllerPipe` TCP controller не используется; `controller: "http://127.0.0.1:9097"` применяется только при пустом `controllerPipe` и отдельно включённом localhost TCP-контроллере. Скрипт не включает его автоматически.

При первом запуске готовой поставки локальный config создаётся из `OpenCodeRouter.config.example.json`. В шаблоне нет controller secret: он читается из стандартного Clash Verge Rev config через `%APPDATA%`. Если Clash установлен нестандартно, исправьте только `secretSource` в созданном локальном файле.

Secret читается из существующего локального Clash config; отдельная копия не хранится. `testProxy` — диагностический порт, `timeoutSeconds` — общий срок проверок узла. `healthProfiles` содержит google/openai/anthropic/openrouter, `healthProfile` выбирает профиль; можно добавить HTTPS URL без изменения кода. `healthCheckUrls`, если задан непустым, имеет приоритет. Доступность выбранного профиля следует проверить в своей сети.

Россия исключается автоматически по флагу 🇷🇺, названиям «Россия»/Russia/Russian Federation и отдельным кодам RU/RUS в имени узла. Такие узлы скрыты из GUI/CLI-списка и меню, пропускаются при сканировании и автоматическом выборе; ручные `use`/`test` также запрещены. Это фильтр названий подписки, а не проверка геолокации IP.

`excludedNodes` — точные имена дополнительных запрещённых узлов. Они скрываются из GUI/CLI-списка и меню, не участвуют в auto и отклоняются при ручной команде `use`/`test`. В шаблоне список исключений пуст; добавьте при необходимости точные имена узлов своей подписки. `preferredRegions` — необязательные подстроки имён, предпочитаемые среди прошедших проверки узлов. Это предпочтение по имени, не геолокация IP. `autoSwitch.minimumImprovementMs` = 100, `cooldownSeconds` минимум 300. При рабочем текущем маршруте в cooldown повторного сканирования нет; нерабочий маршрут и явно запрошенный `-DifferentIp` допускают scan. `autoSwitch.enabled` пока не управляет локальным GUI-монитором; явная команда `auto` также работает независимо от этого флага.

`cache/state.json` хранит последний рабочий узел/IP/время, последнюю смену и результаты. `logs/router-YYYY-MM-DD.log` содержит только узел, IP, health, задержку и причину. При сбое auto восстанавливает исходный узел либо повторно проверенный last-known-good. При недоступном контроллере восстановление физически невозможно — команда сообщает об этом явно. Параметры `autoSwitch.minimumImprovementMs` и `cooldownSeconds` относятся к обычной команде `auto`; GUI-мониторинг выполняется каждые 5 минут и при отказе использует явный последовательный режим `-DifferentIp`.

## Границы маршрута

Маршрут определяется первым совпавшим правилом Clash. Доменные правила и правила входящего порта, расположенные выше PROCESS-NAME, могут направлять запросы другим путём. Диагностический listener проверяет выбранную группу напрямую и обходит таблицу правил. Проверяйте фактическую цепочку приложения в Connections.

После успешной команды `use` или окончательного выбора `auto` утилита точечно закрывает старые соединения `opencode.exe` через API Mihomo, поэтому OpenCode создаёт новые соединения уже через выбранную локацию. Сам процесс OpenCode не завершается. Временные проверки `test` и «Все узлы» ничего не разрывают, а трафик других приложений не затрагивается.

Auto временно переключает OpenCode через тестируемые узлы. Запускайте полный scan между активными запросами. Обычная VPN-группа не переключается.

## Сборка релиза

Все команды выполняются проектным Python. PyInstaller запускается с минимальным `PATH`, после чего отдельный аудит проверяет `COLLECT-00.toc` и совпадение MSVC runtime с PySide6:

```powershell
.\.venv\Scripts\python.exe .\Build_Tools\build_release.py
.\.venv\Scripts\python.exe .\Build_Tools\post_build.py
.\.venv\Scripts\python.exe .\Build_Tools\build_installer.py
.\.venv\Scripts\python.exe .\Build_Tools\deploy_portable.py --destination-parent "$env:USERPROFILE\PortableApps"
```

Итоговая папка находится в `OpenCodeRouter\`, установщик — на рабочем столе Windows либо в папке `--output-dir`. Родительская папка portable-копии задаётся обязательным параметром `--destination-parent`; в примере используется `PortableApps` в профиле пользователя. Существующая подпапка `OpenCodeRouter` в месте назначения заменяется, поэтому сначала сохраните её настройки. Локальные настройки, secret, логи и кэш в поставку не включаются. Portable-архив автоматически не создаётся.
