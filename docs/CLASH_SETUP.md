# Clash Verge Rev: минимальная интеграция OpenCode Router

[← README](../README.md) · [English](CLASH_SETUP.en.md)

[Скачать YAML-фрагмент](../examples/clash-verge/opencode.fragment.yaml)

Это дополнение к **уже работающей подписке Clash Verge Rev**, а не полный профиль.
VPN-узлы, адреса серверов, пароли и подписки в пример не входят. Используй свои
существующие узлы; остальные приложения не требуют дополнительных правил.

## Что нужно приложению

| Элемент | Назначение |
| --- | --- |
| TUN и режим Rule | Перехват трафика `opencode.exe` и применение правил |
| `find-process-mode: strict` | Определение процесса для PROCESS-NAME |
| Selector `OpenCode-Location` | Список реальных узлов, между которыми переключается Router |
| `PROCESS-NAME,opencode.exe,OpenCode-Location` | Направление OpenCode в эту группу |
| HTTP-listener `127.0.0.1:7900` | Проверки Router прямо через выбранную группу |
| `profile.store-selected: true` | Сохранение выбранного узла |
| Локальный API Mihomo | Чтение списка и изменение selector |

TUN захватывает трафик системы; отдельное правило определяет маршрут только OpenCode.
Другие приложения продолжают обрабатываться оставшимися правилами профиля.

## Подключение

1. Сохрани копию своего профиля и существующего Global Script локально.
2. В Clash Verge Rev включи сервисный режим, необходимый для TUN на Windows,
   включи TUN и выбери режим **Rule**, не Global или Direct. Проверь работу обычной подписки.
3. Возьми [фрагмент](../examples/clash-verge/opencode.fragment.yaml). В списке `proxies`
   замени `YOUR-EXISTING-NODE-*` на точные имена узлов из своей подписки, включая пробелы и emoji.
4. Добавь группу в существующий массив `proxy-groups`, listener — в `listeners`,
   правило — в существующий `rules`. Объект `profile` дополни ключом `store-selected`.
   Не создавай повторяющиеся корневые YAML-ключи и не заменяй остальные группы и правила.
5. Применяй изменения через постоянное расширение профиля / Global Script в Clash Verge Rev,
   чтобы обновление подписки не стёрло их. Фрагмент показывает требуемый результат:
   **вставка целиком в Merge без проверки семантики списков не гарантирует сохранение профиля**.
6. Проверь итоговую конфигурацию средствами Clash Verge Rev и примени её.

Если Global Script уже существует, добавляй логику в его `main(config)` перед `return config`.
Не создавай вторую функцию `main` и не заменяй имеющийся скрипт чужой конфигурацией.


### Подписка через proxy-providers

Если подписка содержит понятные направления со ⭐ или 🚀, сохраняй именно их
имена, включая вложенные fallback-группы. Не раскрывай страны до технических
серверов. В [примере Global Script](../examples/clash-verge/opencode-directions.js)
добавь функцию в существующий скрипт и вызови её внутри `main` с точным именем
своей основной VPN-группы. Сохрани существующее правило процесса и listener.
Установка Router сама этот скрипт не применяет.

Правило `PROCESS-NAME,opencode.exe,OpenCode-Location` не зависит от версии или
папки установки OpenCode, пока сетевой процесс называется `opencode.exe`.

Если узлы поступают из `proxy-providers`, вместо поля `proxies` используй имя
**существующего провайдера**, например:

```yaml
proxy-groups:
  - name: OpenCode-Location
    type: select
    use:
      - YOUR-EXISTING-PROVIDER
```

Это альтернативное определение той же группы: не добавляй вторую группу с тем же именем.
Убедись, что провайдер загрузился и Router видит конкретные узлы. Публичный пример
не содержит определения провайдера или URL подписки. Отдельные неподходящие узлы
можно исключить в локальном `OpenCodeRouter.config.json` через `excludedNodes`.

### Порядок правил — важен

Mihomo использует первое совпавшее правило. Для всего трафика OpenCode поставь
PROCESS-NAME выше общих правил, включая `IN-PORT`, доменные правила и финальный `MATCH`.
При этом трафик других процессов по-прежнему обрабатывается оставшимися правилами.

Если отдельные домены OpenCode намеренно должны идти другим маршрутом, оставь их
выше PROCESS-NAME. Такие запросы не подчиняются выбору `OpenCode-Location`.
Диагностический listener обходит таблицу правил,
поэтому успешная проверка Router сама по себе не подтверждает маршрут такого домена.

Сохрани собственное финальное правило `MATCH`; фрагмент не должен его заменять.

### TUN и DNS

Параметры `tun` во фрагменте — отправная точка. Если TUN уже работает, сохрани его
stack, DNS и исключения. В итоговой конфигурации DNS должен разрешать имена серверов
и сайтов; диагностика по HTTPS также зависит от DNS. Не копируй частный адрес DNS
из чужого роутера. DNS hijack, fake-IP и его исключения настраиваются в Clash Verge Rev
под свою сеть; Router не требует отдельного DNS-сервера или конкретного fake-IP-фильтра.

Уже работающий TUN не нужно дублировать в `listeners`. Убедись, что имя процесса
действительно `opencode.exe`: другой бинарник или явно заданный HTTP(S)-прокси у клиента
может использовать другую цепочку. Смотри фактические соединения в Clash.

## Связь с настройками Router

[Шаблон Router](../OpenCodeRouter.config.example.json) уже содержит:

```json
{
  "group": "OpenCode-Location",
  "testProxy": "http://127.0.0.1:7900",
  "controllerPipe": "verge-mihomo"
}
```

Это выдержка, не полный конфиг Router. При первом запуске он создаёт полный локальный
конфиг из шаблона. При `controllerPipe: "verge-mihomo"` Router читает действующее
`external-controller-pipe` из файла `secretSource` при каждом запросе. Если Clash изменил
имя pipe после обновления или смены режима ядра, править локальный конфиг Router не нужно.
Для собственного имени `controllerPipe` используется именно оно. Сверяй
`external-controller-pipe` в итоговой конфигурации Mihomo, а не назначай новый pipe вслепую.
Named pipe не открывает TCP API в сеть; права доступа к локальному pipe важны.

Если используешь собственный TCP API, включи его только на loopback и согласуй
`controller` и пустой `controllerPipe` в Router. Пример не включает TCP API и не меняет secret.
Поле `secretSource` указывает на локальный конфиг Clash; содержимое этого файла публиковать не нужно.

Порт 7900 должен быть свободен: проверь другие listeners, mixed-port и приложения.
Если меняешь порт, одновременно меняй listener и `testProxy`. HTTP-listener доступен
локальным процессам; не меняй `listen` на `0.0.0.0` для этой задачи.

## Проверка

Из корня проекта, после применения конфигурации:

```powershell
# Список узлов; не переключает маршрут
pwsh -NoProfile -File .\OpenCodeRouter.ps1 list
# Проверка текущего узла через диагностический listener
pwsh -NoProfile -File .\OpenCodeRouter.ps1 status
```

Затем выполни запрос в OpenCode и посмотри Connections в Clash: процесс `opencode.exe`,
правило PROCESS-NAME и цепочка `OpenCode-Location` → выбранный узел.
Только это подтверждает фактическую маршрутизацию приложения. `status` проверяет listener.
Временный `test`/`scan` запускай между активными запросами; при обычной окончательной
смене Router закрывает старые соединения OpenCode в своей группе.

| Симптом | Что проверить |
| --- | --- |
| Group missing | Применён ли фрагмент, имя группы, непустой список реальных узлов |
| Named pipe error | Запущен ли Clash, имя pipe и доступ текущего пользователя |
| Отказ 7900 | Конфликт порта, наличие listener, совпадение `testProxy` |
| status успешен, приложение нет | Порядок правил, proxy-переменные клиента, фактический процесс |
| Другие приложения сменили маршрут | Не были ли заменены старые списки rules/groups или финальный MATCH |

Пример проверяется как конфигурационный фрагмент, но не применяется автоматически к твоей сети.
Применение и восстановление профиля выполняются пользователем в Clash Verge Rev.
